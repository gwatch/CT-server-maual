# Кластер CT Lab

Документация по вычислительному кластеру лаборатории: доступ, SLURM,
файловая система, GPU-узлы, контейнеры и вспомогательные сервисы.

## Быстрый старт

```bash
# 1. Заходим на контроллер (только он доступен по ssh)
ssh <username>@ctddev.ifmo.ru -p 22081      # это sphinx (192.168.16.148)

# 2. Ставим задачу в очередь
sbatch --cpus-per-task=10 --mem=20G --time=05:00:00 task.sh

# 3. Смотрим очередь
squeue

# 4. Отменяем задачу
scancel <job_id>
```

> ⚠️ Расчёты на `sphinx` не выполнять — это контроллер SLURM.

## SLURM

На кластере работает **SLURM** — система управления очередью задач.

Схема: вы заходите на `sphinx` и оттуда командами `srun` / `sbatch`
ставите задачу в очередь.

### Очереди

| Очередь | Назначение | Макс. время | QoS для повышения лимитов |
|---------|-----------|-------------|---------------------------|
| **main** | по умолчанию | 14 дней | `--qos=high_mem`, `--qos=high_cpu`, `--qos=high_all` |
| **gpu** | задачи на GPU | 14 дней | — |

По умолчанию: **32 ядра**, **256 GB RAM**, **не более 2 GPU**.
Больше — по запросу (см. [Ограничения](#ограничения)).

### Основные команды

#### `sbatch` — поставить скрипт в очередь

```bash
sbatch --cpus-per-task=10 --mem=20G --time=05:00:00 task.sh
```

Скрипт `task.sh` получит 10 ядер, 20 ГБ памяти и 5 часов.
Если попросит больше — процесс будет убит.

#### `sbatch` на GPU (конкретный узел)

```bash
sbatch --cpus-per-task=10 -p gpu -w kali --gres=gpu:1 \
       --mem=20G --time=05:00:00 task.sh
```

10 ядер, 20 ГБ RAM, 1 GPU, 5 часов, узел `kali`.

#### `srun` — интерактивный шелл

```bash
srun --cpus-per-task=10 --mem=20G --time=05:00:00 --pty bash
```

#### `squeue` — очередь

```bash
squeue
# подробный формат:
squeue -o "%.18i %.9P %.8j %.8C %.8u %.8T %.10m %.10M %.9l %.6D %R"
```

#### `scancel` — отменить задачу

```bash
scancel 123
```

#### Уведомление по почте

```bash
srun --mail-type=END --mail-user=alsergbox@gmail.com sleep 1
```

Если прописать свой адрес в `~/.forward`, `--mail-user` указывать не обязательно.

### Ограничения

- **32 ядра** единовременно на пользователя. Нужно больше (дедлайн?) — писать
  Александру и Алексею.
- **Только чётное число ядер**: из-за гипертрединга физически доступно чётное
  число виртуальных ядер (2 на 1 физическое). Нечётное число сбивает планировщик.
- **256 GB RAM** суммарно на пользователя. Больше — по запросу доступ к очереди
  с повышенными лимитами.

### Важно

- **Всегда указывайте `--time` / timelimit.** Не знаете точно — ставьте TL,
  через который задачу точно убьёте. Формат `--time=3-0` = 3 дня.
- Если стало ясно, что задача не успевает — пишите **Николаю Черкасову**
  с ID задачи и новым лимитом.
- Для продления задач в очереди `main` — тоже к **Черкасову Николаю**.

### Разное

#### Разные CPU на узлах

Для предварительных экспериментов нормализуйте время на частоту CPU:

| Узел | Частота |
|------|---------|
| griffin | 2.4 GHz |
| kraken | 2.5 GHz |

Для аккуратных экспериментов — фиксируйте узлы:

```bash
# запускать только на перечисленных узлах
srun --nodelist=griffin,kraken ...

# если --nodelist не работает — исключить узлы
srun --exclude=host1,host2 ...
```

#### Просмотр использованных ресурсов

```bash
sacct -o user,job,jobname,MaxRSS,reqmem,state,node,time
```

Более удобный вывод (история с даты `-S`):

```bash
SLURM_TIME_FORMAT="relative" \
sacct -o user,job,start,jobname,MaxRSS,reqmem,node,state,time,elapsed \
      -S2019-11-10 | sed "s/00:00:00/00      /g"
```

где `-S YYYY-MM-DD` — с какой даты выводить историю.

#### Job array — много одинаковых задач

Если хочется запустить много мелких однотипных задач — не создавайте их
по отдельности, используйте
[slurm job array](http://slurm.schedmd.com/job_array.html).

**Пример.** `dirs.txt` содержит пути к папкам:

```text
test_one
test_two
test_three
test_four
test_five
```

В каждой папке лежит `task.sh`:

```text
test_five:  task.sh
test_four:  task.sh
test_one:   task.sh
test_three: task.sh
test_two:   task.sh
```

Скрипт для job array:

```bash
#!/bin/bash
#SBATCH --mem=32G
#SBATCH --time=48:00:00
#SBATCH --array=1-5

DIR=$(sed -n "${SLURM_ARRAY_TASK_ID}p" dirs.txt)
cd $DIR
bash $DIR/task.sh
```

Если скрипты одинаковые — используйте один общий `task.sh`.

## Оформление отчётов (LaTeX)

Для сборки отчёта с `gostify.tex` под Linux нужен `xelatex` и шрифты
Times New Roman / Arial / Courier.

```bash
sudo apt-get install texlive-xetex
sudo apt-get install msttcorefonts ttf-mscorefonts-installer
```

Для Arch/pacman — см. <https://wiki.archlinux.org/index.php/Microsoft_fonts>.

### Правила оформления

- На все рисунки и таблицы должна быть ссылка в тексте.
- Перед `\ref` / `\cite` — неразрывный пробел: `на рисунке~\ref{fig_example}`, `в статье~\cite{Author2011}`.
- Заголовок таблицы — **до** таблицы, подпись рисунка — **после**.
- Подписи к рисункам и таблицам не должны повторяться.

```latex
\begin{table}
\caption{Сравнение чего-нибудь}
\begin{tabular}{ l c r }
1 & 2 & 3 \\
4 & 5 & 6 \\
7 & 8 & 9 \\
\end{tabular}
\end{table}

\begin{figure}
\includegraphics{image.png}
\caption{Схема чего-нибудь}
\end{figure}
```

# SLURM — работа с очередью задач

На кластере работает система управления очередью задач **SLURM**.

Схема: вы заходите на `sphinx` и оттуда с помощью команд `srun` или `sbatch`
ставите вашу задачу в очередь.

## Очереди

Организованы очереди:

- **`main`** — очередь по умолчанию, максимальное время работы **14 дней**.
  Если нужно продлить время задачи — обращайтесь к **Черкасову Николаю**.
- **`gpu`** — для запуска задач на GPU, максимальное время работы **14 дней**.

По умолчанию предоставляется **32 ядра** и **256 ГБ памяти**, **не более 2 GPU**.
При необходимости по запросу можно увеличить. При запуске необходимо будет
указать параметр `--qos=high_mem`, `--qos=high_cpu` или `--qos=high_all`.

## Основные команды

Работать со SLURM достаточно просто, там несколько главных команд:

### `sbatch` — поставить скрипт в очередь

```bash
sbatch --cpus-per-task=10 --mem=20G --time=05:00:00 task.sh
```

Запускает скрипт `task.sh` с ограничением в 10 ядер, 20 ГБ памяти и 5 часов
времени работы. Если программа захочет больше ресурсов (больше памяти или
будет дольше работать) — её убьют.

### `sbatch` на GPU (конкретный узел)

```bash
sbatch --cpus-per-task=10 -p gpu -w kali --gres=gpu:1 \
       --mem=20G --time=05:00:00 task.sh
```

Запускает скрипт `task.sh` с ограничением в 10 ядер, 20 ГБ памяти, одним GPU
и 5 часов времени работы на ноде `kali`.

### `srun` — интерактивный шелл

```bash
srun --cpus-per-task=10 --mem=20G --time=05:00:00 --pty bash
```

Запускает шелл в интерактивном режиме с соответствующими ресурсами.

### `squeue` — очередь задач

```bash
squeue
# или подробный формат:
squeue -o "%.18i %.9P %.8j %.8C %.8u %.8T %.10m %.10M %.9l %.6D %R"
```

Выведет информацию о текущей очереди задач.

### `scancel` — отменить задачу

```bash
scancel 123
```

Отменяет задачу 123.

### Уведомление по почте

```bash
srun --mail-type=END --mail-user=alsergbox@gmail.com sleep 1
```

Пошлёт письмо Алексею после завершения задачи. Если прописать свой адрес
в файле `~/.forward`, то этот адрес указывать в командной строке необязательно.

За подробностями см. гугл.

## Ограничения

- Сейчас стоит ограничение в **32 ядра** единовременно на одного пользователя
  на кластере, чтобы один человек не занимал весь кластер.
  Если вам надо больше, например у вас скоро дедлайн — пишите **Александру
  и Алексею**.
- Также из-за технических ограничений **следует резервировать только чётное
  число ядер**.
  Из-за гипертрединга физически можно выделить только чётное число виртуальных
  ядер (по два на одно физическое), указание нечётного числа сбивает
  планировщик с толку.
- Также сейчас стоит ограничение суммарно на **256 ГБ** памяти на пользователя.
  Если вам надо больше, то по запросу можно получить доступ к очереди
  с более высокими ограничениями.

## Разное

- Пожалуйста, **указывайте timelimit**!
  Если не знаете, сколько времени будет работать задача, указывайте такой TL,
  через который вы её точно убьёте.
  Можно использовать в виде `--time=3-0` — TL = 3 дня.
  Если вдруг стало понятно, что задача не успевает завершиться за указанный
  период, напишите **Николаю Черкасову** с указанием идентификатора задачи
  и нового ограничения.
- На узлах несколько разные CPU, поэтому для предварительных экспериментов
  стоит нормализовывать время на частоту процессора (**2.4 ГГц на griffin,
  2.5 ГГц на kraken**). Для более аккуратных экспериментов следует использовать
  опцию `--nodelist`, которой можно указать список узлов, на которых можно
  запускать задачу.
- Если опция `--nodelist` не работает, используйте `--exclude=host1,host2...`.
- С помощью команды `sacct -o user,job,jobname,MaxRSS,reqmem,state,node,time`
  можно посмотреть информацию об использованных ресурсах для завершившихся
  задач. Более удобный output при такой команде:

  ```bash
  SLURM_TIME_FORMAT="relative" \
  sacct -o user,job,start,jobname,MaxRSS,reqmem,node,state,time,elapsed \
        -S2019-11-10 | sed "s/00:00:00/00      /g"
  ```

  где `-S YYYY-MM-DD` — дата, начиная с которой выводить историю.

- Если хочется запустить много маленьких одинаковых задач, то лучше их
  не создавать отдельно, а воспользоваться
  [slurm job array](http://slurm.schedmd.com/job_array.html).

### Пример job array

Файл `dirs.txt` содержит пути к папкам:

```text
> cat dirs.txt

test_one
test_two
test_three
test_four
test_five
```

В каждой из папок лежит таргетный скрипт:

```text
> ls test_*

test_five:
task.sh

test_four:
task.sh

test_one:
task.sh

test_three:
task.sh

test_two:
task.sh
```

Для того чтобы сформировать job array, можно написать следующее:

```bash
#!/bin/bash
#SBATCH --mem=32G
#SBATCH --time=48:00:00
#SBATCH --array=1-5

DIR=$(sed -n "${SLURM_ARRAY_TASK_ID}p" dirs.txt)
cd $DIR
bash $DIR/task.sh
```

В случае, если скрипты одинаковые, лучше использовать один файл `task.sh`.
